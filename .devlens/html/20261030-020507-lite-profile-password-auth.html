2. static_key secrets provider

  • Exactly one of ROUTER_SECRETS_MASTER_KEY (base64 of 32 bytes) or ROUTER_SECRETS_MASTER_KEY_FILE; the check applies to the api only.
  • Key id static:<16 hex of sha256>. Previous keys are decrypt-only (ROUTER_SECRETS_PREVIOUS_MASTER_KEYS / _FILES), then api secrets rotate.
  • Shared internal/secrets/keyring with local. local: key ids are pinned by a test, and local is still allowed only in the local environment.

3. deploy/lite: how the internal listener works in production

web nginx ──https (verify internal CA)──▶ api :8080   (public listener, HTTPS too: one TLS config for both listeners)
worker  ──mTLS client cert CN=worker──▶  api :8443   ROUTER_WORKLOAD_AUTH=mtls, MTLS_ALLOWED=worker,preview
preview ──mTLS client cert CN=preview─▶  api :8443
certs-init (one-shot, network none): CA key kept in its own volume; leaf certs re-issued only when missing or near expiry
api healthcheck: /app health https://127.0.0.1:8080/readyz   (new Go probe, not busybox wget)
  • The guards are unchanged. Production rejects static_token, an internal listener without client CAs, and insecure cookies.
  • Production needs HTTPS in front: an external TLS terminator, or the optional docker-compose.tls.yml. Trial mode is init.sh --trial, which sets ROUTER_ENV=staging and insecure cookies.
  • With metrics off, the backend stays prometheus pointed at an absent host and fails fast. Route metrics reader null, alerts off, and the metric-based attention detectors are skipped. The UI shows "—" or "Unavailable" instead of erroring.
  • Disaster recovery: back up a pg_dump plus the .env file. Losing ROUTER_SECRETS_MASTER_KEY makes saved credentials unrecoverable.

5. Risks and open items

  • Never run on docker: the nginx HTTPS upstream, the TLS override, the Prometheus HTTPS scrape and certs-init (Compose ≥ 2.17, openssl installed at build time) are unproven. deploy/lite/smoke.sh is ready for your run.
  • All services read one certs volume as uid 65532, so the worker can read the api and preview keys. This is acceptable on a single host.
  • Account lockout lets an attacker lock a known email (DoS trade-off). An admin reset does not clear the lock; it expires on its own.
  • Switching an existing install from vault, kms or local to static_key does not migrate stored secrets. The lite profile assumes a fresh install.
  • Behind a proxy, the per-IP login limit counts per proxy until set_real_ip_from is configured (see the README).
